# Knowledge Schema Field Review

这份文档用于逐行核对 `prisma/schema.prisma`。当前 schema 的目标是支撑一个可长期演化的 AI 知识库：结构化录入、全文检索、语义检索、AI 引用回答、版本追踪和后台任务。

## Design Principles

| Principle | Decision |
|---|---|
| Core searchable fields | Use normal columns, not JSON. |
| Main taxonomy | Use the `Category` table with stable codes like `01`, not a free `String`. |
| Database enums | Use Prisma enums only for lifecycle/security boundaries: `visibility`, `status`, `maturity`, `freshness`, and job status. |
| Controlled codes | Use `String` + `VocabularyTerm` for `type`, chunk kinds, source types, relation types, query modes, and other values likely to grow. |
| Flexible metadata | Use `Json` for fields that may evolve often. |
| Long text and AI retrieval | Store chunks separately in `RecordChunk`. |
| Translations | Store primary-language content on `KnowledgeRecord`; store other languages in `RecordTranslation`. |
| Vector search | Store embeddings only on `RecordChunk`, not on both records and chunks. |
| FTS / vector indexes | Store searchable structures in `RecordSearchIndex` and `RecordEmbedding`; add GIN/pgvector indexes with raw SQL migrations. |
| User system | Not added yet. Keep `actorId`, `createdBy`, `userId` as future hooks. |

## Cross-Field Invariants

These rules should be enforced in Zod, import code, service methods, or raw SQL checks where Prisma cannot express them cleanly.

| Rule | Enforcement |
|---|---|
| `confidence` must stay in `0..1`. | Zod validation. |
| Controlled `String` fields must exist in `VocabularyTerm`. | Zod/service validation against seeded vocabulary. |
| `KnowledgeRecord.categoryCode` must use an active `Category.code`. | Database relation plus service check for `isActive`. |
| `SearchResultLog.chunkId`, when present, must belong to the same `recordId`. | Service validation or raw SQL check. |
| `SearchFeedback` should reference at least one target: query, answer, record, or chunk. | Zod validation. |
| `RecordEmbedding.dimensions` must match the provider/model embedding length. | Embedding worker validation. |
| `RecordEmbedding.contentHash` must match the embedded chunk text hash. | Embedding worker validation. |
| `RecordSearchIndex.contentHash` must match the indexed record/chunk aggregate. | Search-index rebuild worker validation. |
| Raw text in `payload`, `rawPayload`, `before`, `after`, and `snapshot` should be bounded. | Import/audit retention policy. |

## KnowledgeRecord

Main table. This is the schema your skill-generated knowledge objects will eventually map into.

| Field | Type | Required | Purpose | Notes |
|---|---:|---:|---|---|
| `id` | `String` | yes | Internal stable ID. | Generated by Prisma with `cuid()`. |
| `slug` | `String` | yes | Human-readable unique URL/key. | Used for `/records/[slug]`. |
| `externalKey` | `String?` | no | Globally unique external key. | Prefer namespace plus source ID, such as `openrouter:model:gpt-oss-120b`. |
| `externalId` | `String?` | no | Raw external source ID. | Not globally unique; used for source tracing. |
| `checksum` | `String?` | no | Content fingerprint. | Used for dedupe and change detection. |
| `schemaVersion` | `Int` | yes | Knowledge object schema version. | Default `1`; useful for future import compatibility. |
| `type` | `String` | yes | Record form/type. | Controlled by `VocabularyTerm(namespace=record_type)`; examples: `CONCEPT`, `TOOL`, `CASE_STUDY`, `DECISION`. |
| `categoryCode` | `String` | yes | Stable main category code. | References `Category.code`; examples: `01`, `07`, `15`. |
| `visibility` | `RecordVisibility` | yes | Visibility. | Default `INTERNAL`; examples: `PUBLIC`, `INTERNAL`, `PRIVATE`. |
| `status` | `RecordStatus` | yes | Publishing/workflow state. | Default `DRAFT`; examples: `DRAFT`, `REVIEW`, `PUBLISHED`, `ARCHIVED`. |
| `maturity` | `RecordMaturity` | yes | How mature/reliable the record is. | Default `SEED`; examples: `SEED`, `REVIEWED`, `VALIDATED`. |
| `freshness` | `RecordFreshness` | yes | Freshness state. | Default `UNKNOWN`; examples: `FRESH`, `STALE`, `NEEDS_REVIEW`. |
| `confidence` | `Float?` | no | Confidence score. | Suggested range `0..1`, enforced by Zod. |
| `language` | `String` | yes | Primary language. | Default `zh`; can be `zh`, `en`, `fr`, etc. |
| `title` | `String` | yes | Main title. | Required for search and display. |
| `summary` | `String?` | no | Main summary. | Important for list results and AI context. |
| `body` | `String?` | no | Main text content. | Keep reasonable; very long content should be chunked. |
| `problem` | `String?` | no | Problem this record addresses. | Good for Q&A matching. |
| `recommendation` | `String?` | no | Recommended action/conclusion. | Good for AI answer synthesis. |
| `metadata` | `Json?` | no | General flexible metadata. | Indexed with GIN. Do not put core filters only here. |
| `applicability` | `Json?` | no | When this record applies. | Example: environment, scale, constraints. |
| `compatibility` | `Json?` | no | Compatibility matrix. | Example: model/provider/framework support. |
| `tradeoffs` | `Json?` | no | Pros/cons and alternatives. | Useful for decision records. |
| `evidence` | `Json?` | no | Evidence summary. | Keep detailed sources in `Source`. |
| `metrics` | `Json?` | no | Quantitative observations. | Example: latency, cost, benchmark result. |
| `curation` | `Json?` | no | Review/curation metadata. | Example: reviewer notes, quality checklist. |
| `extensions` | `Json?` | no | Future extension bucket. | Last-resort flexible field. |
| `createdAt` | `DateTime` | yes | Creation timestamp. | Database default `now()`. |
| `updatedAt` | `DateTime` | yes | Last update timestamp. | Prisma-managed `@updatedAt`. |
| `publishedAt` | `DateTime?` | no | First publish time. | Set when status becomes published. |
| `lastVerifiedAt` | `DateTime?` | no | Last manual or automated verification. | Useful for stale knowledge. |
| `reviewAfter` | `DateTime?` | no | Next review date. | Used for maintenance queues. |
| `archivedAt` | `DateTime?` | no | Archive timestamp. | Prefer soft archive over deletion. |
| `tags` | relation | no | Related tags. | Via `KnowledgeRecordTag`. |
| `category` | relation | yes | Main taxonomy category. | References `Category` by `categoryCode`. |
| `translations` | relation | no | Record translations. | Via `RecordTranslation`. |
| `aliases` | relation | no | Alternative names. | Via `Alias`. |
| `keywords` | relation | no | Search keywords. | Via `Keyword`. |
| `sources` | relation | no | Evidence/source links. | Via `KnowledgeRecordSource`. |
| `versions` | relation | no | Record history. | Via `RecordVersion`. |
| `chunks` | relation | no | Text chunks. | Via `RecordChunk`. |
| `searchIndexes` | relation | no | Full-text index documents. | Via `RecordSearchIndex`. |
| `searchIndexJobs` | relation | no | Search index rebuild jobs. | Via `SearchIndexJob`. |
| `embeddingJobs` | relation | no | Related embedding jobs. | Via `EmbeddingJob`. |
| `importItems` | relation | no | Import item details. | Via `ImportJobItem`. |
| `searchResults` | relation | no | Search result logs. | Via `SearchResultLog`. |
| `feedback` | relation | no | Search feedback. | Via `SearchFeedback`. |
| `outgoingRelations` | relation | no | Directed relations from this record. | Example: depends_on, replaces. |
| `incomingRelations` | relation | no | Directed relations to this record. | Reverse lookup. |

| Field | Type | Required | Purpose | Notes |
|---|---:|---:|---|---|
| `id` | `String` | yes | Search index ID. | Generated. |
| `recordId` | `String` | yes | Parent record ID. | One index per record per language. |
| `language` | `String` | yes | Index language. | Default `zh`. |
| `title` | `String` | yes | Title index text. | High-weight FTS field. |
| `summary` | `String?` | no | Summary index text. | Medium/high weight. |
| `body` | `String?` | no | Body index text. | Usually aggregated from chunks. |
| `tags` | `String?` | no | Aggregated tag text. | Helps tag recall and exact matches. |
| `aliases` | `String?` | no | Aggregated alias text. | Helps synonym/acronym recall. |

## Future User System

The current schema deliberately avoids adding users too early. It only leaves hooks:

| Current hook | Where | Future use |
|---|---|---|
| `AuditLog.actorId` | audit logs | Link to `User.id` or `ApiKey.id`. |
| `RecordVersion.createdBy` | versions | Track who changed a record. |
| `SearchQueryLog.userId` | query logs | Track logged-in search/AI usage. |
| `SearchQueryLog.sessionId` | query logs | Track anonymous usage. |

When login, permissions, or multi-user editing becomes real, add these models:

| Future model | Purpose | Likely fields |
|---|---|---|
| `User` | Human user account. | `id`, `email`, `name`, `role`, `status`, `createdAt`, `updatedAt`, `lastLoginAt`. |
| `ApiKey` | Skill/import/API access. | `id`, `name`, `keyHash`, `scope`, `status`, `lastUsedAt`, `expiresAt`, `createdBy`. |
| `Session` | Optional server-side sessions. | `id`, `userId`, `expiresAt`, `ipAddress`, `userAgent`. |
| `UserRecordRole` | Per-record ownership/review rights. | `userId`, `recordId`, `role`. |
| `SavedSearch` | User saved filters or searches. | `userId`, `name`, `query`, `filters`. |
| `Feedback` | Search/AI answer quality feedback. | `userId`, `queryLogId`, `answerId`, `recordId`, `chunkId`, `rating`, `comment`. |

Recommended first roles:

| Role | Purpose |
|---|---|
| `owner` | Full system control. |
| `admin` | Manage records, jobs, tags, sources. |
| `editor` | Create and edit knowledge records. |
| `reviewer` | Verify, publish, and mark freshness. |
| `reader` | Search and view published records. |
| `agent` | API/skill worker account, limited to import or query scopes. |

| Area | Decision to confirm |
