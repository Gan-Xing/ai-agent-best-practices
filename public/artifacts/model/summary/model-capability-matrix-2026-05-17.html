关键备注Key Notes

1. Kimi 的通用 JSON 不是“完全不会”，而是快跑里超时过一次。1. Kimi does support JSON; the generic probe timed out once in the fast baseline run.
第一张表里 generic json 仍按基线脚本结果记为 🟥❌；但原厂专项里的 JSON Mode 已经单独跑通。
Kimi is not fundamentally missing JSON support. The generic JSON probe timed out in the fast baseline run, while native JSON Mode passed in the dedicated Kimi suite.
2. Qwen 的 code_interpreter 目前还不能算“实锤通过”。2. Qwen code interpreter is not confirmed yet.
它返回了正确答案 1728，但没有出现 code_interpreter_call 或 usage.x_tools.code_interpreter，所以这轮仍记 🟥❌。
Qwen answered correctly, but we still lack tool-call evidence. No code_interpreter_call and no usage.x_tools.code_interpreter means we cannot prove the hosted tool actually ran.
3. Qwen 的 web_extractor 必须绑定 web_search 一起测。3. Qwen web extractor must be paired with web search.
单独调用会被官方接口拒绝；所以当前的通过结果，表示的是“组合链路可用”，不是“独立 extractor 工具可单跑”。
Qwen's web extractor only passed when paired with web search. Standalone extractor invocation was rejected by the native API.
4. Qwen 的 native MCP 这轮更像环境未激活，而不是模型本身不会。4. Qwen native MCP looks blocked by environment activation, not raw model ability.
模型明确回了“未连接或激活 MCP 服务”，因此这项失败更像账号或服务侧状态问题。
The native MCP probe looks more like an account or service activation gap than a pure model capability miss.
5. DeepSeek 的 tool loop 旧失败，已经被专项测试拆清楚了。5. DeepSeek's old tool-loop failure was traced to protocol handling.
通用表里的失败来自旧 smoke 没有回传 reasoning_content；专项里已经验证：不回传会失败，回传后会恢复成功。
The old DeepSeek multi-turn failure was a protocol issue. Missing reasoning_content fails; replaying it restores the loop successfully.
6. 这张表是“当前已验证快照”，不是永久结论。6. This matrix is a verified snapshot, not a timeless verdict.
部分单元格代表当前脚本、当前账号、当前平台状态下的真实表现，后续继续补测时这些格子会更新。
This is a verified snapshot, not a timeless verdict. Some cells depend on the current scripts, account entitlements, and platform state.
