关键备注Key Notes

0. 通用基线必须优先走 /responses。0. Shared baselines must prefer /responses.
凡是当前可走 /responses 的模型，shared baseline 一律用 /responses。只有厂商官方没有 /responses，或某项能力只能通过厂商原生接口验证时，才退到官方原生接口，并把 transportPolicy 写进测试报告。
Whenever a model can use /responses, shared baselines must use /responses. Only providers without an official /responses path, or capabilities that require provider-native APIs, may fall back to the native API, with transportPolicy recorded in the report.
0b. shared hosted web search 只代表 OpenRouter web 插件。0b. Shared hosted web search means the OpenRouter web plugin only.
第一张表里的 hosted web search 不再混合厂商原生网页搜索，只表示 OpenRouter 提供的 plugins: [{ id: "web" }]。DeepSeek V4 Pro 经 OpenRouter 已能返回带 url_citation 的联网结果；DeepSeek 原厂 native web_search 仍在平台原生专项里按 / 处理。
The shared hosted web search row no longer mixes provider-native web search; it only means OpenRouter's plugins: [{ id: "web" }]. DeepSeek V4 Pro through OpenRouter returned web results with url_citation; DeepSeek's official native web_search remains / in the provider-native table.
1. Kimi 的 JSON / Structured Output 已按官方 native 结果覆盖。1. Kimi JSON / Structured Output now follows official native results.
旧表里的 Kimi 通用 JSON 失败和严格结构化输出跳过是旧快跑口径，不应继续保留。`2026-05-22.r3` 官方 native 复跑已经确认 jsonMode 和 response_format: json_schema 的 structuredOutput 都通过。Kimi 当前官方主路径是 Chat Completions，不是 /responses。
The older Kimi generic JSON failure and strict-output skip were stale fast-run signals. The `2026-05-22.r3` official native rerun confirmed both jsonMode and response_format: json_schema structuredOutput passed. Kimi's current official main path is Chat Completions, not /responses.
2. Qwen 的强制 tool_choice 必须在关闭 thinking 后再测。2. Qwen forced tool_choice should be measured with thinking disabled.
官方文档明确说明思考模式不支持强制工具选择；`2026-05-22.r3` 的共享 smoke 在 forced probe 中显式使用 reasoning.effort=none 后，`toolChoiceStability` 才稳定转成了 🟩✅。
The official Qwen docs explicitly say forced tool choice is unsupported in thinking mode. The `2026-05-22.r3` shared rerun only turned `toolChoiceStability` into a stable 🟩✅ after forcing reasoning.effort=none.
3. Qwen 的原生 code_interpreter 目前应按“不稳定”处理。3. Qwen native code interpreter should currently be treated as unstable.
`2026-05-21` 曾经拿到过 codeInterpreterCalls=1 与 usageCount=1；`2026-05-22` 早些时候多次复跑没有真实工具痕迹，但最新 `run-2026-05-22.selfhosted-mcp.json` 又拿到了 codeInterpreterCalls=1 与 usageCount=1。因此矩阵改为带波动备注的 PASS：有真实能力，但调用是否触发不稳定。
We got a real codeInterpreterCalls=1 / usageCount=1 trace on `2026-05-21`. Earlier `2026-05-22` reruns had no real tool trace, but the latest `run-2026-05-22.selfhosted-mcp.json` again produced codeInterpreterCalls=1 / usageCount=1. The matrix therefore marks it as a noted PASS: the capability exists, but triggering it is unstable.
4. Qwen 的 web_extractor 必须绑定 web_search 一起测。4. Qwen web extractor must be paired with web search.
单独调用会被官方接口拒绝；所以当前的通过结果，表示的是“组合链路可用”，不是“独立 extractor 工具可单跑”。
Qwen's web extractor only passed when paired with web search. Standalone extractor invocation was rejected by the native API.
5. Qwen 的 native MCP 依然没有形成真实调用痕迹。5. Qwen native MCP still lacks a verified call trace.
`2026-05-22` 的三次原生复跑都只返回“当前环境未直接接入 MCP”的解释文本，`mcpCalls=0`；额外手工探测发现中国区百炼 MCP endpoint 对当前 US key 返回 `InvalidApiKey`，US / intl 同类 endpoint 返回 `404`。最新 `run-2026-05-22.selfhosted-mcp.json` 使用本站自建 SSE MCP server 后，模型只输出了 {"name":"roll_dice"} 这类普通文本，仍没有真实 mcp_call。当前链路固化为不可验证。
All three native reruns on `2026-05-22` only returned explanatory prose with mcpCalls=0. Manual probes showed the China-region Bailian MCP endpoint returns `InvalidApiKey` for the current US key, while the US / intl equivalents return `404`. The latest `run-2026-05-22.selfhosted-mcp.json` used this site's self-hosted SSE MCP server, but the model only emitted plain text like {"name":"roll_dice"} and still produced no real mcp_call. The current path is frozen as unverifiable.
6. DeepSeek 的旧红格已经被清干净，空白项也不再是“未知”。6. DeepSeek's old red cells are cleared, and its empty cell is no longer “unknown.”
通用 smoke 的递归回归已经修掉；`2026-05-22.r3` 的 thinking-loop 专项 8 项全部通过，包括 jsonMode、strictFunctionCalling、reasoning_content 回传恢复、thinking 关闭和 context cache。DeepSeek 默认 thinking mode 下强制 tool_choice 会返回 “Thinking mode does not support this tool_choice”，但 `2026-05-22.r3` 共享 smoke 在 forced probe 中显式关闭 thinking 后，toolChoiceStability 3/3 通过。
The smoke-regression recursion bug is fixed, and the `2026-05-22.r3` thinking-loop suite passed all 8 probes, including reasoning_content recovery, disabled thinking, strict function calling, and context caching. DeepSeek returns “Thinking mode does not support this tool_choice” for forced tool_choice in default thinking mode, but the `2026-05-22.r3` shared smoke disables thinking for forced probes and passed toolChoiceStability 3/3.
7. Gemini 的早期红格目前更像瞬时波动。7. Gemini's early red cells now look more like transient drift.
后续两轮完整 smoke 都通过了 `toolArgumentAccuracy / parallelTools / multi-turn tool loop / longContext`，而单独抽测的 `hosted web search` 也 3/3 成功，所以当前更合理的结论是“整体可用，但仍需观察”，而不是继续按系统性失败处理。
The next two full smoke reruns both passed `toolArgumentAccuracy / parallelTools / multi-turn tool loop / longContext`, and a dedicated `hosted web search` spot check passed 3/3. The better current read is “generally usable, still worth watching,” not a systemic failure.
8. Kimi 官方 native 工具专项已经补齐。8. Kimi's official native tools suite has been closed.
`MOONSHOT_API_KEY` 已恢复，`2026-05-22.r3` 官方 native 复跑 13 个 probe 全部通过：builtin $web_search、Formula discovery、fetch、quickjs、code_runner、memory、jsonMode、structuredOutput、文件上传与文件问答。`OpenRouter` fallback 仍只作为共享基线补充，不覆盖官方 native 结论。
`MOONSHOT_API_KEY` is now available. The `2026-05-22.r3` official native rerun passed all 13 probes: builtin $web_search, formula discovery, fetch, quickjs, code_runner, memory, jsonMode, structuredOutput, and file upload + file QA. The OpenRouter fallback remains supplemental and does not overwrite official-native conclusions.
9. OpenRouter 三列不是原厂能力缺失。9. OpenRouter columns do not mean native provider capabilities are missing.
`GPT / Claude / Gemini` 当前共享基线走 `OpenRouter`。由于当前不准备接官方原生 API，原厂专项里官方已有但本项目不接入的能力标成 暂不测。这表示当前范围不覆盖，不表示厂商没有能力。
The current `GPT / Claude / Gemini` shared baseline goes through OpenRouter. Because official native APIs are out of scope for now, documented native capabilities that this project does not integrate are marked deferred. This is a scope decision, not a claim that the providers lack those features.
10. DeepSeek 原厂 hosted tools 当前按不适用处理。10. DeepSeek native hosted tools are currently treated as not applicable.
DeepSeek V4 Pro 官方 API 当前重点是 ChatCompletions / Anthropic 兼容、thinking、reasoning_content、function calling 和 context cache。官方 API 文档没有暴露可直接等价于 web_search / web_extractor / code interpreter / MCP / file_search 的原厂 hosted tool，所以平台原生专项里这些格子用 /。这不影响 shared 表里通过 OpenRouter web 插件测得的 hosted web search。
DeepSeek V4 Pro's official API currently focuses on ChatCompletions / Anthropic compatibility, thinking, reasoning_content, function calling, and context caching. The official API docs do not expose native hosted tools directly equivalent to web_search / web_extractor / code interpreter / MCP / file_search, so those provider-native cells use /. This does not conflict with the shared hosted web search result through OpenRouter's web plugin.
11. 这张表是“当前已验证快照”，不是永久结论。11. This matrix is a verified snapshot, not a timeless verdict.
部分单元格代表当前脚本、当前账号、当前平台状态下的真实表现，后续继续补测时这些格子会更新。
This is a verified snapshot, not a timeless verdict. Some cells depend on the current scripts, account entitlements, and platform state.

这部分只列在现有 key 和现有服务器条件下还能推进的工作；需要新增官方 API、vector store 或外部账号配置的项目不再列为当前推进项。 This section lists only work that can move forward with the current keys and server setup. Items requiring new official APIs, vector stores, or external account setup are no longer in the next-test queue.

OpenAI / Anthropic / Gemini 官方原生 API 当前不接入，所以对应原生专项统一标为“暂不测”。这不是能力否定，只是当前项目范围调整；共享基线仍保留 OpenRouter 路径。
OpenAI / Anthropic / Gemini official native APIs are not being integrated for now, so their native-provider cells move from “pending” to “deferred.” This is a scope decision, not a claim that the providers lack those capabilities. The shared baseline keeps the OpenRouter path.
2. 需要外部资源的项目不再作为下一步2. Externally gated work is no longer next
Qwen native file_search 和 shared hosted file search 都需要 vector store / 百炼知识库 ID。只有 API Key 不足以测试这些链路，所以当前保持 SKIP 或暂不测。
Qwen native file_search and shared hosted file search both need vector stores / Bailian knowledge-base IDs. API keys alone are not enough, so these paths remain SKIP or deferred.
3. 我还能独立处理的事项3. Work that can still be done here
已完成矩阵语义、hover 注释、证据来源和已有 key 的 Qwen 回归。Qwen MCP 已用本站自建最小 SSE MCP server 做过可追踪验证；仍没有 mcp_call，因此当前链路固化为不可验证。后续还能独立推进的是报告脚本清理和 Kimi / DeepSeek / OpenRouter 的常规回归。
Matrix semantics, hover notes, source evidence, and the Qwen rerun with existing keys are done. Qwen MCP has now been tested with this site's self-hosted minimal SSE MCP server; it still produced no mcp_call, so the current path is frozen as unverifiable. Remaining self-service work is report-script cleanup plus regular Kimi / DeepSeek / OpenRouter regressions.
