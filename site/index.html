15 Directions

一个生产级 Agent，通常会在这 15 个工程面同时暴露问题。

01Models

模型能力、长上下文、结构化输出、工具调用、成本和延迟。

 02Instruction

任务拆解、提示词、Schema、输出约束与版本管理。

 03Runtime

Agent loop、状态、会话、重试、流式和恢复机制。

 04Skills

能力包、触发、组合、检索和技能评测。

 05Tools

工具 schema、参数校验、权限、错误和结果设计。

 06MCP

Tools、Resources、Prompts 与协议化能力暴露。

 07RAG

解析、切分、Embedding、检索、引用和 freshness。

 08Memory

用户记忆、项目记忆、上下文压缩和污染控制。

 09Workflow

图工作流、Router、Supervisor、Handoff 和并行执行。

 10Agent UI

运行时间线、工具调用展示、人工审批和反馈界面。

 11Evaluation

任务成功率、工具正确率、RAG Eval 和回归测试。

 12Trace

Run log、Replay、Latency、Token Cost 和 Failure Analysis。

 13Security

Prompt injection、权限、敏感数据和红队测试。

 14Sandbox

浏览器、Shell、代码执行、文件边界和 Playwright Agent。

 15Adapters

LiteLLM、OpenRouter、Vercel AI SDK 与 Runtime 兼容性。

Experiment Flow

每个判断尽量都应该能落到一次实验、一次对比或一次复盘里。

  1. Question先把要验证的问题写清楚，例如某个模型的工具调用是否稳定。
  2. Setup固定模型、Runtime、工具 schema、测试集、指标和失败判定标准。
  3. Run记录输入、输出、tool call、trace、latency、token 和错误样例。
  4. Review把结论回写到 docs、comparisons 或 best-practices，避免只停留在聊天结论。
Input Surfaces

Prompt、工具描述、MCP 能力、上下文注入、检索结果和用户反馈。

Observed Signals

Tool correctness、structured output validity、step trace、latency、cost、hallucination rate。

Reusable Output

实验结论、失败模式、兼容矩阵、最佳实践和后续设计约束。
